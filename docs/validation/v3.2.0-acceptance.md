## 功能与统计口径核对

- primary 由 SAM flag 确定；`total.raw_reads` 保持 primary 记录口径。符合 [STAR 官方说明](https://github.com/alexdobin/STAR/blob/master/extras/doc-latex/STARmanual.tex)：默认一条 primary，`AllBestScore` 可能多条 primary；实现没有使用 `HI==1` 判断 primary。
- 只有 `NH=1` 和明确告警的缺失 NH 回退记录贡献 RNA 深度。映射的 primary 上 NH/HI 非法值报错。
- `NH>1` 按输入序号、完整 QNAME、read1/read2 标识精确去重；状态跨染色体保留。小内存强制溢写、多层归并和写入失败清理均有测试。
- GTF/GFF2 普通和 gzip 注释、header 对齐、exon 合并及 gene body 减 exon 的 intron 分布均覆盖。独立逐碱基 oracle 核对 `M/=/X` 分布、read 多数决及并列顺序。
- 链方向使用方向明确的 exon；双方向重叠不参与推断。双端协议、无注释及 XS 与注释方向不一致的情形均覆盖。
- 文本 `[RNA]` 和 JSON `rna` 已接通。DNA/RNA 默认分别为 8/10 文件，summary-only 分别为 7/9 文件。串并行、溢写前后输出逐字节一致，失败时旧报告保留，临时文件清理。
- README 已说明用法、字段、read end 口径、缺失标签回退和 3.1→3.2 行为变化。

上述夹具由 `tests/rna_oracle.py` 生成，属于受控合成数据；本次未新增实现修改。

## 性能验收限制

本次核对了此前保存的原始 JSON 与 [性能报告](dna-performance.md)，没有重复完整性能基准。相对于 3.1.0 (`af559ba`)，宽参考四线程场景十轮复测的 CPU 中位数回退为完整输出 **2.24%**、summary-only **2.87%**；墙钟中位数分别回退 **3.97%**、**2.18%**。合成数据输出一致性检查通过。

报告中对 alignment delta/reducer 的解释是候选原因，尚无 profiling 或对照实验将其证实。原计划要求调查超过 1% 的稳定回退，这一项目前只有复测证据，仍需补充根因调查。现有数据也不能证明生产 BAM/CRAM 的性能。
